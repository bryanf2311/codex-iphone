# Codex — iPhone Coding Harness

A pocket-sized coding harness. Edit code, run JavaScript and Python locally, and pair-program with an AI model that runs **entirely on your iPhone** — no cloud, no subscription, your code never leaves the device.

## What it does

- **Code editor** (Monaco, with a guaranteed textarea fallback for older WebViews)
- **Runs** JavaScript (sandboxed iframe), Python (Pyodide), and HTML preview
- **On-device AI** via `@huggingface/transformers` v3 — ONNX Runtime Web / WASM, so it works on iOS Safari
- **Remote API** as a fallback — any OpenAI-compatible endpoint (DeepSeek, OpenAI, Groq, OpenRouter)
- **Files** stored in IndexedDB, autosave, export/import project as JSON
- **PWA** installable to the iPhone home screen, fully offline shell

## Bring a model onto the iPhone (no token, no account)

Open **Setup → Bring a model onto this iPhone** and pick **one** of three paths:

### ① Pick a curated model (one tap)
Four pre-vetted, ungated models. First tap downloads the weights; from then on it's fully offline.
- **SmolLM2 360M** — tiny, fast on iPhone
- **Qwen2.5 Coder 1.5B** — best balance for code
- **SmolLM2 1.7B** — good chat
- **Phi-3.5 mini** — best quality, slowest

### ② Sideload from your Files app (offline, zero internet)
If you already downloaded a HuggingFace ONNX model on your computer (AirDrop, iCloud Drive, Files app), tap **Pick folder…** or **Pick files…** in the Setup tab. The app imports the `.onnx`, `tokenizer.json`, `config.json`, etc. directly into local storage. No network needed.

### ③ Paste any non-gated HuggingFace repo id
Tap **Fetch** after entering e.g. `onnx-community/Qwen2.5-Coder-1.5B-Instruct`. The app pulls weights from `huggingface.co` directly. No token required for public repos.

### Advanced: Hugging Face token
Gated repos (Gemma 3 E2B, etc.) need a token. Open the **Advanced · Hugging Face token** disclosure in Setup, paste your token, save. Most users can ignore this.

After the model loads once, it lives in your phone's Cache Storage. Restart the app, go offline, reopen — the model still works.

## Build a .ipa — three ways, ranked by ease

### Option A: GitHub Actions (no Mac needed) ⭐

The repo includes `.github/workflows/build-ipa.yml`. A free macOS GitHub runner builds the `.ipa` for you in the cloud.

1. Create a new GitHub repo, push this project to it.
2. The workflow runs on every push to `main`. Click the green ✓ or red ✗ next to your commit, then open the workflow run.
3. Scroll to the bottom of the run page, find **Artifacts → `codex-ipa`**, download it, unzip.
4. Install `Code.ipa` on your iPhone:
   - **Easiest: [Sideloadly](https://sideloadly.io)** — free, Mac/Windows, uses your Apple ID, 7-day re-signing. Free Apple IDs work.
   - **[AltStore](https://altstore.io)** — keeps re-signing automatically for 7 days.
   - **iMazing / 3uTools** — drag-and-drop on Mac/Windows.

If you push a tag like `v1.0.0`, the `.ipa` is also attached to the GitHub release automatically.

**Optional signed-build mode.** If you have a paid Apple Developer account and want a directly-installable `.ipa` (no Sideloadly), add these repo secrets under **Settings → Secrets and variables → Actions**:
- `BUILD_CERTIFICATE_BASE64` — your `Apple Distribution` `.p12`, base64-encoded.
- `P12_PASSWORD` — the password for the `.p12`.
- `PROVISIONING_PROFILE_BASE64` — your iOS provisioning profile, base64-encoded.
- `KEYCHAIN_PASSWORD` — any random string the runner uses to lock a temporary keychain.
- `APPLE_TEAM_ID` — your 10-character Apple Team ID.

To encode: `base64 -i cert.p12 | pbcopy`.

### Option B: Local Mac
```bash
bash make-ipa.sh
```
The script verifies Xcode/Node/CocoaPods, runs `cap add ios`, syncs the bundle, opens Xcode. You then **Product → Archive** → **Distribute App**.

### Option C: Web-only PWA
```bash
npx http-server www -p 8080
# on iPhone: open URL in Safari → Share → Add to Home Screen
```
No `.ipa`, but works for trying the app out.

## Layout

```
.
├── .github/workflows/build-ipa.yml   ← CI build (Option A)
├── www/                              ← web bundle (built by `npm run build`)
├── ios/                              ← generated by `cap add ios` on Mac runner
├── js/                               ← source JS
├── css/                              ← source styles
├── icons/                            ← PWA icons (192, 512)
├── manifest.json
├── capacitor.config.json
├── make-ipa.sh                       ← Mac build script (Option B)
└── sw.js                             ← service worker (web install only)
```

## Files of interest

- `js/localModel.js` — on-device model loader. Three ingestion paths (curated, sideload, HF download). Per-family prompt templating (gemma3, llama3, phi3, qwen, smollm2, mistral, auto). Cache introspection.
- `js/runner.js` — sandboxed iframe for JS, Pyodide loader for Python.
- `js/chat.js` — provider abstraction (local vs. remote).
- `js/app.js` — UI orchestration.
